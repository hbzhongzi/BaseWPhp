# 项目目录结构说明

## 项目定位

这是一个基于 ThinkPHP 8 的综合后台 API 模板，按“共享平台能力 + 多小程序独立业务域”组织。`sample` 是结构示例，不代表已实现真实微信登录或业务。

## 顶层目录

```text
Mytotal/
├── app/
│   ├── common/             跨小程序共享的稳定能力
│   ├── middleware/         项目解析等横切中间件
│   └── mini/               每个小程序独立的业务域代码
├── api/                    公共接口、用户和上传接口文档
├── database/
│   ├── migrations/         版本化 up/down SQL 迁移（含字段注释迁移）
│   ├── migrate.php         迁移执行器（status/up/down）
│   └── schema.sql          公共表初始化快照
├── config/
│   └── mini_programs.php   小程序注册表（仅非敏感元数据）
├── doce/                   项目目录结构说明
├── docs/                   项目开发规范与维护文档
├── extend/                 Composer 未覆盖的扩展类/第三方集成
├── public/                 Web 唯一公开目录、HTTP 入口及静态资源
│   └── storage/images/     按小程序/年月分区的固定图片存储目录（运行时生成且已忽略版本控制）
├── route/
│   └── mini_programs/      各小程序独立路由文件
├── runtime/
│   ├── program_logs/       按小程序/日期分区的 API JSON Lines 日志（运行时生成）
│   └── ...                 缓存、临时文件等其他运行时数据
├── vendor/                 Composer 依赖（由 Composer 管理）
├── view/                   服务端模板；纯 API 项目通常很少使用
├── .example.env            环境变量示例，不含真实密钥
├── composer.json           PHP 依赖与 PSR-4 自动加载配置
└── think                    ThinkPHP 命令行入口
```

## `app/` 应用代码

```text
app/
├── middleware/
│   ├── RequestId.php            请求 ID 中间件
│   ├── ResolveMiniProgram.php   解析项目身份（不负责登录认证）
│   └── Authenticate.php          access token 认证
├── mini/{programKey}/         小程序独立业务域
│   ├── controller/v1/         项目版本化 API 控制器
│   ├── service/                项目业务用例与事务编排
│   ├── model/                  项目数据模型
│   └── validate/               项目参数校验器
├── common/                     跨项目复用能力
│   ├── controller/v1/          健康检查、启动配置、认证、用户、文件接口
│   ├── exception/              业务异常
│   ├── controller/             原模板演示控制器
│   ├── response/               API 统一响应
│   ├── service/                微信登录、令牌、文件服务
│   ├── model/                  公共表模型
│   ├── support/                加密、项目上下文与 ProgramLogger 日志工具
│   └── validate/               共享校验器
├── BaseController.php          控制器公共能力及参数校验入口
├── ExceptionHandle.php         全局异常处理入口
├── Request.php                 项目请求对象扩展点
├── middleware.php              全局中间件注册清单
├── provider.php                容器绑定
├── service.php                 应用服务注册
└── event.php                   事件绑定/监听
```

实际业务优先放在 `app/mini/{programKey}/`。只有语义、数据权限和生命周期都跨项目一致的能力才放入 `app/common/`；公共代码禁止反向依赖具体小程序目录。

## 配置与路由

- `config/mini_programs.php` 是已注册小程序白名单，仅存 `programKey`、显示名、启用状态等非敏感元数据。微信 AppSecret 等凭据应从 `.env` 或部署密钥系统加载。
- `route/app.php` 加载公共路由并按注册表加载 `route/mini_programs/{programKey}.php`。
- 每个项目路由使用 `/api/{programKey}/v1` 前缀，必须挂载项目解析中间件；登录后接口还需挂载真正验证令牌的认证中间件。
- `ResolveMiniProgram` 将已注册项目写入请求中间件上下文，控制器可通过 `$request->middleware('mini_program')` 读取。它不是认证，也不是数据隔离的替代品。

## 其他目录

- `api/`：接口索引、公共接口、用户兼容说明、图片上传说明及数据库契约文档；入口为 `api/README.md`，正式公共接口基线为 `api/common.md`。
- `public/`：HTTP 入口与公开静态资源；站点根目录必须指向这里，不能指向项目根目录。用户图片固定存储于 `public/storage/images/{programKey}/YYYY/MM/`，只允许安全校验后的图片扩展名，Web 服务器需禁止执行脚本。
- `runtime/`：运行时可写目录，不应提交日志、缓存或用户上传内容。API 日志按 `runtime/program_logs/{programKey}/YYYY-MM-DD.log` 组织，JSON Lines 每行记录请求 ID、路由模板、状态、耗时和脱敏异常元数据，不保存请求正文或凭据。
- `vendor/`：Composer 安装生成的依赖目录，不直接修改其中代码。
- `extend/`：项目自定义扩展类；新代码优先使用 `app/` 下的 PSR-4 命名空间。
- `view/`：ThinkPHP 模板目录；纯 API 项目通常很少使用。
- `database/migrations/`：版本化数据库迁移，已执行文件禁止修改，只能新增迁移。
- `database/migrate.php`：执行 `status`、`up`、`down`，并将版本写入 `sys_migration`。
- `database/schema.sql`：公共表初始化快照，适合新库快速导入；持续开发优先使用迁移器。
- `composer.lock`：锁定依赖版本，应用项目应纳入版本管理。

接口文档更新规则：公共接口改动必须同步 `api/common.md`、必要的专题文档和联调示例；目录结构、部署方式、日志或存储规则变化时同步更新本文件、`doce/项目初始化部署文档.md` 和 `docs/项目开发规范.md`。

## 请求处理流程

```text
小程序请求 /api/{programKey}/v1/...
  → public/index.php
  → route/app.php 加载对应项目路由
  → ResolveMiniProgram 校验项目是否启用并建立可信项目上下文
  → 认证中间件（仅登录后路由）→ 授权校验
  → app/mini/{programKey}/controller → validate → service → model/repository
  → app/common/response 统一 JSON 响应
```

每个数据库查询、缓存键、文件路径、异步任务都必须遵循项目数据边界。完整接口、隔离、安全和测试要求见 [项目开发规范](../docs/项目开发规范.md)。

排查 API 请求时，先从响应中的 `request_id` 找到对应小程序和日期的日志文件；日志不可读或写入失败时，应检查 PHP-FPM 用户对 `runtime/program_logs/` 的权限及磁盘空间。

首次部署、环境变量、数据库初始化和 Web 配置见 [项目初始化部署文档](项目初始化部署文档.md)。
