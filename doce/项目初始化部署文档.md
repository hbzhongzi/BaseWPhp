# 项目初始化部署文档

## 1. 部署目标

本文用于新环境首次部署 ThinkPHP 综合小程序后台。部署完成后应能访问公共健康检查，并具备数据库、密钥、上传目录和 Web 入口的基本条件。

生产部署必须使用 HTTPS，Web 根目录指向项目的 `public/`，不能把项目根目录暴露给公网。本文示例命令以 Linux/macOS 为主，Windows 开发环境使用等价命令即可。

## 2. 环境要求

- PHP 8.0+；建议 PHP 8.2
- Composer 2
- MySQL 8.0+（最低兼容 5.7 时需确认排序规则和 JSON 行为）
- PHP 扩展：`pdo_mysql`、`openssl`、`mbstring`、`fileinfo`
- Nginx 或 Apache；生产不使用 PHP 内置开发服务器
- 微信小程序已配置服务器域名、业务域名和合法 HTTPS 证书

检查版本：

```bash
php -v
php -m
composer --version
```

## 3. 获取代码与依赖

```bash
git clone <repository-url> mytotal
cd mytotal
composer install --no-dev --optimize-autoloader
```

不要修改 `vendor/`。发布时使用与 `composer.lock` 一致的依赖版本；开发环境可执行 `composer install` 安装开发依赖。

## 4. 环境变量

复制示例文件并生成唯一密钥：

```bash
cp .example.env .env
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
```

在 `.env` 中至少配置：

```dotenv
APP_DEBUG=false
APP_URL=https://api.example.com
APP_KEY=替换为上一步生成的随机值

DB_DRIVER=mysql
DB_TYPE=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=mytotal
DB_USER=mytotal_app
DB_PASS=替换为数据库密码
DB_CHARSET=utf8mb4
DB_PREFIX=

WECHAT_SAMPLE_APPID=微信小程序 AppID
WECHAT_SAMPLE_SECRET=微信小程序 AppSecret
```

注意：

- `.env` 不提交版本库，AppSecret、数据库密码和 `APP_KEY` 只能由部署密钥系统或服务器环境注入。
- 每个小程序在 `config/mini_programs.php` 配置自己的 `appid_env`、`secret_env`，配置文件只保留环境变量名，不保存密钥值。
- `APP_KEY` 一旦用于加密 openid/手机号，不得随意更换；更换前必须设计数据重加密和令牌全部失效方案。

## 5. 注册小程序

在 `config/mini_programs.php` 增加项目注册项：

```php
'shop_a' => [
    'name'       => '商城 A',
    'enabled'    => true,
    'appid_env'  => 'WECHAT_SHOP_A_APPID',
    'secret_env' => 'WECHAT_SHOP_A_SECRET',
    'features'   => [],
],
```

同时完成：

1. 在服务器环境配置对应的 `WECHAT_SHOP_A_APPID` 和 `WECHAT_SHOP_A_SECRET`。
2. 创建 `app/mini/shop_a/`，只放该小程序自己的控制器、服务、模型和校验器。
3. 创建 `route/mini_programs/shop_a.php`，只放该小程序业务路由；公共接口会自动生成 `/api/shop_a/v1/...`。
4. 在数据库 `sys_mini_program` 中插入同名 `program_key`、微信 AppID 和启用状态。

注册表和数据库必须同时存在且状态一致。停用项目时先将数据库和配置设为停用，再清理回调、定时任务和密钥。

## 6. 初始化数据库

先创建数据库和最小权限账号：

```sql
CREATE DATABASE mytotal CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'mytotal_app'@'127.0.0.1' IDENTIFIED BY '替换为强密码';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX
  ON mytotal.* TO 'mytotal_app'@'127.0.0.1';
FLUSH PRIVILEGES;
```

初始化公共表（推荐使用迁移器）：

```bash
php database/migrate.php status
php database/migrate.php up
```

迁移器会创建 `sys_migration`（带 `DB_PREFIX` 时自动加前缀）记录已执行版本。每个迁移文件包含一个 `*.up.sql` 和一个 `*.down.sql`。当前迁移器针对 MySQL DDL 不使用 PDO 事务，因为 MySQL 的建表/删表操作会隐式提交；迁移失败后应根据 `status` 和数据库实际表状态人工确认再重试。回滚最近一次迁移：

```bash
php database/migrate.php down
```

生产执行迁移前必须备份数据库，并先在预发环境验证。`down` 会删除对应迁移创建的表，只允许在确认数据可恢复时执行。

首次初始化也可以直接导入完整快照：

```bash
mysql -h127.0.0.1 -P3306 -u mytotal_app -p mytotal < database/schema.sql
```

导入后写入项目注册数据，示例：

```sql
INSERT INTO sys_mini_program
  (program_key, name, appid, status, created_at, updated_at)
VALUES
  ('sample', '示例小程序', 'wx-your-appid', 1, NOW(), NOW());
```

当前仓库提供 `database/migrations/` 迁移文件、`database/migrate.php` 迁移器和 `database/schema.sql` 初始化快照。当前公共表字段注释由 `202610300002_add_public_column_comments` 增量迁移补充。后续表结构变更必须新增带时间序列的 up/down migration，禁止修改已经执行过的迁移文件；CI 应执行空库迁移、升级库迁移和回滚验证。

## 7. 目录权限与上传目录

```bash
mkdir -p runtime/program_logs public/storage/images
chown -R www-data:www-data runtime/program_logs public/storage/images
chmod -R u=rwX,g=rwX,o= runtime/program_logs
chmod -R u=rwX,g=rX,o= public/storage/images
```

将 `www-data` 替换为实际 PHP-FPM/Web 用户和组。`runtime/program_logs/` 只允许 PHP 进程及运维组读写，不应作为静态资源暴露；`public/storage/images/` 是图片固定存储目录，需要 PHP 写入、Web 静态服务器读取。若 Nginx 与 PHP-FPM 使用不同用户，应通过专用共享组配置必要的目录/文件读取权限，不要对整个项目开放写权限。

图片按 `public/storage/images/{programKey}/YYYY/MM/{随机文件名}.{jpg|png|webp}` 保存，URL 前缀默认为 `/storage/images`。Nginx/Apache 必须禁止存储目录执行 PHP、PHTML、PHAR 等脚本，并确保项目根目录以外的 `runtime/` 不可通过 Web 访问。Nginx 的 PHP location 之前可加：

```nginx
location ~* ^/storage/.*\.(php|phtml|phar)$ { deny all; }
```

Apache 虚拟主机也应禁用上传目录脚本处理，例如在站点配置中设置（按实际路径调整）：

```apache
<Directory "/var/www/mytotal/public/storage/images">
    Options -ExecCGI
    <FilesMatch "(?i)\.(php[0-9]?|phtml|phar|pht|phps)$">
        Require all denied
    </FilesMatch>
</Directory>
```

按小程序区分的 API JSON Lines 日志位于 `runtime/program_logs/{programKey}/YYYY-MM-DD.log`。日志记录请求 ID、路由模板、方法、HTTP 状态、耗时和异常类型/代码；不记录 Token、密钥、请求/响应正文或异常原始消息。通过响应头/响应 JSON 的 `X-Request-Id` / `request_id` 在对应项目和日期日志中定位请求。日志按日期分文件；保留天数、归档和清理应由服务器的日志轮转/运维策略配置，避免直接将日志目录映射到公网。

模板尚未接入内容安全服务，上传后 `security_status` 为 `pending` 且接口不返回公开 URL。生产上线前需接入审核流程，只有 `passed` 文件才可公开展示；不能将 `pending` 视为审核通过。若改用对象存储，应通过受控适配器替换存储实现，不把永久密钥写入代码。

## 8. Nginx 示例

```nginx
server {
    listen 443 ssl http2;
    server_name api.example.com;
    root /var/www/mytotal/public;
    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    # 必须放在通用 PHP location 之前，禁止上传目录执行脚本。
    location ~* ^/storage/.*\.(php|phtml|phar)$ { deny all; }

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_pass 127.0.0.1:9000;
    }

    location ~ /\. { deny all; }
}
```

实际环境需补齐证书、HSTS、请求体大小、超时和日志配置。不要把 `vendor/`、`config/`、`.env`、`runtime/` 暴露为静态资源。

## 9. 启动与验收

开发环境：

```bash
php think run
```

生产环境使用 Nginx/Apache + PHP-FPM，不执行上述开发服务器。部署后依次检查：

```bash
php think version
php think route:list
curl -i https://api.example.com/api/sample/v1/health
curl -i https://api.example.com/api/sample/v1/app/bootstrap
curl -i https://api.example.com/api/sample/v1/users/me
```

预期结果：

- `health` 返回 HTTP 200、`code=0`。
- `app/bootstrap` 返回公开配置，不包含 AppSecret、数据库连接或内部权限。
- `users/me` 未携带 token 返回 HTTP 401、`code=40100`。
- 未注册项目返回 HTTP 404、`code=40401`。
- 响应包含 `X-Request-Id` 和 JSON `request_id`。
- 每次 API 请求都应写入 `runtime/program_logs/{programKey}/YYYY-MM-DD.log`，可用响应中的 `request_id` 找到 JSON Lines 记录；未认证请求应记录对应 HTTP 状态及错误类型/业务码，不得出现请求头 Token。

## 10. 上线检查

- [ ] `APP_DEBUG=false`，`.env` 权限和密钥托管正确。
- [ ] HTTPS、微信服务器域名、上传域名和回调域名已配置。
- [ ] 数据库备份、恢复演练和迁移回滚方案已验证。
- [ ] 小程序注册表、`sys_mini_program` 和环境变量三者一致。
- [ ] access/refresh token 生命周期、撤销和重放检测已测试。
- [ ] 跨小程序数据隔离测试通过，所有查询带 `program_id`。
- [ ] 上传 MIME、文件签名、大小和内容安全检查已启用。
- [ ] 图片目录固定为 `public/storage/images/`，PHP 脚本执行已禁用，Web/PHP 权限按最小范围配置。
- [ ] 每个小程序的 `runtime/program_logs/{programKey}/` 均可写且不对公网开放；日志保留、归档和磁盘告警已配置。
- [ ] 日志脱敏、请求 ID、错误告警和旧接口调用量监控已接入。
- [ ] 公共接口和每个小程序业务接口的接口文档、负责人和版本号已登记。
