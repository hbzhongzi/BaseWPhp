# 综合后台项目开发规范

## 1. 架构目标

本后台服务多个微信小程序。平台能力尽量复用，但每个小程序的产品功能、数据边界和迭代节奏相对独立。

```text
小程序 A ─┐                  ┌─ A 的控制器/服务/模型/校验器
小程序 B ─┼→ 共享平台能力/API →├─ B 的控制器/服务/模型/校验器
小程序 C ─┘                  └─ C 的控制器/服务/模型/校验器
```

共享代码只放跨小程序稳定且语义一致的能力，例如微信登录适配、令牌验证、统一响应、日志、文件存储和基础设施封装。商品、订单、会员权益等业务不得因为“看起来相似”就放入共享层；先独立实现，出现稳定复用需求后再抽象。

## 2. 小程序注册与路由

1. 在 `config/mini_programs.php` 注册稳定的 `programKey`（小写英文、数字、下划线），例如 `shop_a`。
2. 为该项目创建 `app/mini/{programKey}/` 业务目录和 `route/mini_programs/{programKey}.php` 路由文件。
3. 路由前缀使用 `/api/{programKey}/v1/...`，路由组必须挂载 `ResolveMiniProgram`，禁止客户端自行提交租户 ID 来覆盖路由身份。
4. 配置 `enabled=false` 应立即拒绝该项目接口。删除/停用项目应同时评估令牌、回调、定时任务和数据保留策略。
5. `ResolveMiniProgram` 只解析项目身份，不验证用户身份。需要登录的路由还必须挂载经审核的认证中间件；根据用户角色做操作授权。

小程序标识不是秘密，也不是授权凭据。所有查询、更新、缓存键、文件路径和异步任务都必须以可信上下文中的 `programKey`/内部 `program_id` 做隔离过滤，不能仅依赖 URL 隔离。

## 3. 目录与命名

- `app/mini/{programKey}/controller/v1/`：HTTP 输入输出编排，不写复杂业务与 SQL。
- `service/`：该小程序的业务用例，负责事务边界和跨模型编排。
- `model/`：该小程序的数据模型；共享表必须显式纳入租户范围。
- `validate/`：参数校验规则；校验输入格式与范围，不承担授权。
- `route/mini_programs/{programKey}.php`：只定义该小程序的路由。
- `app/common/`：已确认可复用的跨项目代码。公共能力应避免反向依赖 `app/mini/*`。
- `app/middleware/`：项目解析、认证、限流等横切能力；每个中间件职责单一。
- `config/`：非敏感默认配置；密钥从 `.env` 或部署密钥系统读取。
- 用户上传图片固定落在 `public/storage/images/{programKey}/YYYY/MM/`；服务端生成随机文件名，禁止使用客户端路径/文件名拼接磁盘路径。
- API 访问日志固定落在 `runtime/program_logs/{programKey}/YYYY-MM-DD.log`，使用 JSON Lines，便于以 `request_id` 检索。

PHP 类名使用 `PascalCase`，方法/变量使用 `camelCase`，数据库字段和 `programKey` 使用 `snake_case`。每个小程序独立命名空间，禁止跨项目直接调用对方的 Controller/Model；需要协作时定义共享服务接口或事件。

## 4. 共享登录与认证边界

- 登录入口和令牌验证可共享，微信 `appid`、`secret`、登录配置按小程序分别管理；不能让客户端通过任意传入的 `appid` 选择凭据。
- 后端通过可信路由项目上下文选择对应微信配置，调用 `jscode2session`；`code` 一次性使用，不记录明文 `session_key`/`secret`。
- 明确账号映射策略：建议以 `(program_id, openid)` 作为小程序内用户唯一键；如需跨小程序统一会员，必须取得业务授权并单独设计 UnionID/主账号关联。
- 令牌需有明确签名/随机性、过期、续期、撤销、设备策略及密钥轮换方案。认证中间件验证签名和会话状态，并将已验证身份放入请求上下文。
- 登录成功不等于有权访问所有资源。每个写操作都进行资源归属校验和角色/权限校验。
- 不在日志、错误响应、埋点中输出 access token、openid 全量值、手机号、密钥或敏感请求体。

当前模板已提供项目解析、access token 认证和公共接口骨架，但微信密钥、数据库、完整授权策略和迁移流程仍需按项目落地；接入前需补充威胁建模、接口测试和安全评审。

## 5. 数据隔离与数据库

先选择并记录隔离策略：

- 共享数据库/共享表：业务表必须包含 `program_id`，唯一索引也必须包含该字段；仓储/查询入口统一强制追加租户条件。
- 共享数据库/独立表：表名需有稳定项目域前缀，仍需防止服务误查其他项目表。
- 独立数据库：每个项目配置独立连接和迁移流程，避免在运行时拼接未经白名单验证的连接名。

禁止只靠“开发者记得加 where 条件”。建议在 Service/Repository 中统一注入租户上下文，并为越权访问、跨租户 ID 猜测编写测试。金额使用整数最小货币单位或 `DECIMAL`，不要用浮点数；事务覆盖完整业务写流程。

数据库变更必须可审阅、可在测试/预发重复执行，并附回滚或恢复方案。使用 `database/migrate.php` 执行版本化 up/down migration；已执行迁移禁止修改，新增迁移需纳入 CI 的空库、升级和回滚验证。MySQL DDL 会隐式提交，不能假设建表迁移具备完整事务回滚能力，必须依靠备份、幂等 SQL 和人工验收。

## 6. API 规范

- URL：`/api/{programKey}/v{主版本}/{资源}`；资源名复数，HTTP 动词表达操作。删除等不可逆操作明确使用 `DELETE` 或具名命令接口。
- JSON 字段采用 `snake_case`；统一响应为 `code`、`message`、`data`、`timestamp`。HTTP 状态码表达协议结果，`code=0` 表示业务成功。
- 分页固定使用 `page`、`page_size`，设置最大页大小；列表响应在 `data` 中包含 `items`、`total`、`page`、`page_size`。
- 校验必填、类型、长度、枚举、边界和幂等键；拒绝未声明字段或按明确 allowlist 写入，避免批量赋值漏洞。
- 错误响应不可泄露 SQL、堆栈、文件路径、微信响应密钥等内部细节。
- 对微信回调、支付通知、创建订单等重试场景实现签名校验、幂等和重复投递处理。
- CORS、频率限制、上传类型/大小、超时和重试策略必须明确配置，不使用宽泛通配作为生产默认值。

### 6.1 接口实现与文档同步

- 新增或修改接口时，必须同时更新路由、Controller、校验器、Service、接口文档和联调示例。
- 公共接口文档以 `api/common.md` 为准；兼容旧客户端的路径、字段和状态码必须单独标注，并记录下线日期。
- 接口响应字段使用 `snake_case`，新增字段需说明是否必返、默认值、空值语义和兼容策略；禁止用同一字段在不同接口表达不同含义。
- 文件接口必须说明存储路径、访问权限、审核状态和删除策略；不能在文档中把 `pending` 描述为已审核通过。
- 文档中的命令、路由和 JSON 示例应在本地或预发环境实际验证后提交。

## 7. 代码与测试要求

- 控制器薄、Service 表达用例、Model/Repository 负责持久化，校验与授权分开。
- 外部微信 API 封装为共享 Adapter，设置连接/读取超时、错误分类和脱敏日志；单元测试使用替身，不在测试中调用真实微信服务。
- 每个新增接口至少覆盖成功、参数错误、未认证/无权限、租户隔离和关键异常路径。
- 业务 Bug 修复先补回归测试；支付、退款、用户身份、跨租户数据改动需要额外安全审查。
- 不直接修改 `vendor/`；依赖变更提交 `composer.json` 与 `composer.lock`。
- 格式遵循 PSR-12；提交前运行 PHP lint、测试和静态检查（项目落地 CI 后设为必需项）。
- 文档变更也要检查链接、路径、状态码和配置名；至少执行 `php think route:list` 和涉及 PHP 文件的 `php -l`。

## 8. 配置、发布与运维

- `.env` 不提交；`.example.env` 只放变量名和假值。生产 `APP_DEBUG=false`，密钥使用部署密钥管理，定期轮换。
- Web 根目录必须是 `public/`；`runtime/` 与上传目录不能直接执行 PHP。
- `public/storage/images/` 只存放图片静态资源；Web 进程不得在该目录执行 PHP/脚本。运行时日志放入 `runtime/program_logs/` 并限制读取权限。
- 日志按项目标识、日期和请求 ID 分类，只记录路由模板、HTTP 状态、耗时及异常类型/代码；不写请求体、响应体、Token、密钥、openid、手机号或原始异常消息。健康检查与依赖就绪检查分开。
- 发布按“迁移 → 兼容代码上线 → 验证 → 清理旧字段/旧接口”的顺序；回滚前确认数据库兼容。
- 新项目上线清单：注册配置、路由、微信密钥、数据隔离策略、认证权限、回调域名、隐私合规、监控告警、备份恢复和接口文档。
